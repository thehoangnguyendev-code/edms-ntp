Status: built and checked on DEV; **not committed**. Decisions: Decision Log `REPORT-CHARTJS-2026-11-16` and `AUDIT-TAB-TIMELINE-2026-11-16` (owner decisions; QA has not confirmed).

## 1. Charts of the reports (Chart.js, on the server)

### What changed
- **Eight kinds of chart** in a template (`ReportLayout.Chart.TYPES`): `BAR`, `HORIZONTAL_BAR`, `PIE`, `DOUGHNUT`, `POLAR_AREA`, `RADAR`, `LINE`, `AREA` (the last two are trends by month and need a date field; `ReportLayout.Chart.trend`).
- **New service `chart-renderer`** (`deploy/chart-renderer`: Node 22, Chart.js 4, chartjs-node-canvas 5; compose service, internal network only, no published port, read-only root, all capabilities dropped, optional `X-Chart-Token`; the report fonts are the backend's `fonts/` mounted as a build context). `POST /render` answers a PNG; `GET /health`.
- **Backend:** `ChartImageRenderer`, `ChartJsRenderer` (HTTP client, 5 s connect, 30 s request, only the groups are sent), `ReportCharts.png` (the old Java2D drawing is removed), `ReportChartSamples` (made-up groups, as the server groups them), endpoint `POST /reports/templates/layout/chart-preview` (permission as the layout preview), the PDF and the XLSX use the picture (`ReportPresentationRenderer`), `ReportLayoutPreview` uses `trend`.
- **Failure:** a renderer that cannot be reached or answers something that is not a PNG is `REPORT_CHART_RENDERER_UNAVAILABLE` (an `IllegalStateException`: the run is tried again, 3 attempts, then fails with its reason); a chart the renderer refuses is `REPORT_CHART_INVALID`. No fallback drawing.
- **Placement (unchanged, now verified against the real renderer):** one chart page per chart before the table, after the cover when there is one; one `Analysis n` sheet per chart in an XLSX (figures and picture). A CSV has no chart (plain text has no sheets); nothing was added for it.
- **Frontend:** `recharts` and the shadcn chart wrapper removed; `chart.js` added. The editor (`ReportChartsEditor`) offers the eight kinds (trends only with a date field) and shows the picture the server draws (`ReportChartPreview`, debounced, aborts the older request). The live charts that are not reports (dashboard `ActivityBarChart` and donut, Backup and Restore overview, Storage Usage) are Chart.js in the browser (`components/ui/chart/ChartCanvas.tsx`).
- Compose / env: `chart-renderer` service, `APP_REPORT_CHART_RENDERER_URL`, `APP_REPORT_CHART_RENDERER_TOKEN`, `CHART_RENDERER_TOKEN` in `deploy/env/*.env.example`.

### Impact analysis
`getNavigation`-style analysis was not run for these files: they are new classes and one deleted drawing method. GitNexus `impact` upstream on `edms-ntp`, run after the edit: `ReportCharts` and `ReportPresentationRenderer` callers are the run worker (`ReportPlatformService`) and the layout preview; read by hand. `detect_changes` not run (nothing committed; the tree is large).
